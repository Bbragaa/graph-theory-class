# exercício 29 - estratégia em sistema real

## cenário

- dados frequentemente atualizados
- busca precisa ser muito rápida
- ordenação completa tem custo alto


## análise das opções

### busca sequencial

- complexidade: o(n)
- não precisa de ordenação
- problema: muito lenta para grandes volumes com milhares de buscas por segundo

### busca binária

- complexidade: o(log n)
- precisa dos dados ordenados
- problema: reordenar após cada atualização custa o(n log n), o que é caro quando os dados mudam com frequência

### outra estratégia: tabela hash

- busca em o(1) em média
- inserção em o(1) em média
- não precisa de ordenação
- ideal para o cenário descrito

## decisão

a melhor escolha é usar uma tabela hash.

justificativa:
- a busca é o(1) em média, muito mais rápida que sequencial e binária
- a inserção também é o(1), então os dados podem ser atualizados sem custo alto
- não precisa manter os dados ordenados, eliminando o custo de reordenação

em sistemas reais, estruturas como tabelas hash ou árvores balanceadas (como árvores avl ou red-black) são usadas justamente para equilibrar o custo de inserção e busca ao mesmo tempo.


## comparativo

| estratégia       | busca    | inserção  | precisa ordenar |
| ---------------- | -------- | --------- | --------------- |
| busca sequencial | o(n)     | o(1)      | não             |
| busca binária    | o(log n) | o(n)      | sim             |
| tabela hash      | o(1)     | o(1)      | não             |
